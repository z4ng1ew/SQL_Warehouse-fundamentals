Это диаграмма, иллюстрирующая подход **Билла Инмона** к построению DWH (Data Warehouse — хранилища данных). Давай разберу по элементам.

## Центральный цилиндр — «Single Version of Truth»

**Single Version of Truth** (единая версия правды) — это главное ядро хранилища данных. Идея в том, что все данные компании собраны в **одном месте**, очищены, согласованы и нормализованы (то есть без дубликатов и противоречий). Это и есть «единственный источник истины» — если кто-то хочет узнать что-то о данных компании, он идёт сюда.

Синие квадратики внутри цилиндра — это **таблицы/сущности** данных, хранящиеся в нормализованном виде (3NF — третья нормальная форма, то есть данные максимально разбиты на отдельные таблицы без избыточности).

## Внешние блоки — «Data Mart Layer»

**Data Mart** (витрина данных) — это небольшое тематическое хранилище, «вырезка» из основного DWH для конкретного отдела или задачи. Например, витрина для отдела продаж, витрина для финансистов, витрина для маркетинга.

На картинке видно **три витрины** (розовая слева вверху, розовая слева внизу, зелёная справа). Каждая получает только **те данные, которые ей нужны** из центрального хранилища.

## Стрелки и «SCV»

**SCV** здесь — это **Single Customer View** (единое представление клиента) — концепция, когда вся информация о конкретном клиенте/сущности собирается из разных частей хранилища в единый профиль.

Цветные стрелки (красные, зелёные, жёлтые) показывают, как разные витрины **выбирают разные срезы данных** из центрального хранилища. Каждая витрина «тянет» к себе свой набор таблиц/сущностей через свой SCV.

## Суть подхода Инмона

Вся философия на картинке: **сначала** строим единое нормализованное хранилище (цилиндр), **потом** из него нарезаем витрины для конкретных потребителей. Это подход «сверху вниз» (top-down). В противоположность Кимбаллу, который предлагает сразу строить отдельные витрины (подход «снизу вверх» / bottom-up), а потом при необходимости интегрировать их.
