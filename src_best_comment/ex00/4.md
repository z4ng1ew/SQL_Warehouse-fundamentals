Здесь **два правила сортировки** через запятую:

```sql
ORDER BY id, updated DESC
--       ^^  ^^^^^^^^^^^^
--       1-е    2-е правило
```

**`id`** — сначала сортируй по id по возрастанию (ASC — по умолчанию, если не указано). Все EUR (id=100) вместе, потом USD (id=200), потом JPY (id=300).

**`updated DESC`** — внутри каждого id сортируй по дате **от новых к старым** (DESC — descending, по убыванию).

Результат сортировки:

```
id=100, EUR, 0.9,    2022-03-03 ← новейшая для id=100
id=100, EUR, 0.89,   2022-03-02
id=100, EUR, 0.87,   2022-03-02
id=100, EUR, 0.9,    2022-03-01 ← старейшая для id=100
id=200, USD, 1,      2022-03-03 ← новейшая для id=200
id=200, USD, 1,      2022-03-02
id=300, JPY, 0.0087, 2022-03-03 ← новейшая для id=300
id=300, JPY, 0.0079, 2022-03-01
```

И тут вступает `DISTINCT ON (id)` — берёт **первую** строку из каждой группы. А первая — это та, у которой `updated` самый свежий (потому что DESC). Именно так мы получаем **последний курс** каждой валюты.

Если бы написали `ORDER BY id, updated ASC` — DISTINCT ON взял бы **самый старый** курс. А нам нужен самый свежий, поэтому DESC.





















---


```sql
updated - что это за команда ?
```



Это **не команда**. Это просто **название столбца** в таблице `currency`. Вспомни структуру таблицы:

```sql
create table currency(
    id          bigint,
    name        varchar,
    rate_to_usd numeric,
    updated     timestamp   ← вот этот столбец
);
```

`updated` — это столбец типа `timestamp` (временна́я метка), который хранит **дату и время** обновления курса. Авторы задания выбрали такое имя, потому что оно означает «обновлено» — то есть «когда этот курс был записан».

Могли назвать как угодно — `created_at`, `event_time`, `date_modified`, `abc123` — SQL всё равно. Это просто имя, которое придумал разработчик базы.

Пример значений в этом столбце:

```
2022-03-03 13:31:00
2022-03-02 12:31:00
2022-03-01 15:36:00
```

Поэтому когда мы пишем `ORDER BY id, updated DESC` — мы говорим «отсортируй по столбцу updated от новых дат к старым».
