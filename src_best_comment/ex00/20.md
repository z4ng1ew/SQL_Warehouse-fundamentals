## Разбор по частям

```sql
FULL JOIN "user" AS u ON v.user_id = u.id
^^^^^^^^^ ^^^^^^ ^^^^ ^^ ^^^^^^^^^^^^^^^^^
тип       таб-   алиас   условие соединения
соеди-    лица
нения
```

**`FULL JOIN`** — тип соединения. Сохраняет **все** строки из **обеих** таблиц, даже если пара не найдена.

**`"user"`** — таблица пользователей. В кавычках, потому что `user` — зарезервированное слово в PostgreSQL (без кавычек PostgreSQL подумает, что это системная команда).

**`AS u`** — алиас. Вместо `"user".name` пишем короче `u.name`.

**`ON v.user_id = u.id`** — условие: связываем `user_id` из volumes с `id` из user.

## Почему FULL JOIN, а не INNER JOIN

**INNER JOIN** — оставляет только строки, где есть пара в обеих таблицах:

```
volumes:  user_id=1 ←→ user id=1 (Иван)     ✓ совпало
volumes:  user_id=4 ←→ user ???              ✗ нет пары — СТРОКА ПРОПАДЁТ
```

**FULL JOIN** — сохраняет **все** строки, даже без пары:

```
volumes:  user_id=1 ←→ user id=1 (Иван)     ✓ совпало
volumes:  user_id=4 ←→ user ???              ✓ сохранится, name=NULL
user:     id=??? ←→ volumes ???              ✓ если бы был user без баланса
```

## Зачем это в задании

Задание говорит: «обработать **все** данные, включая аномалии». В balance есть `user_id=4`, а в таблице user такого пользователя **нет**. FULL JOIN сохраняет эту строку, а `COALESCE(u.name, 'not defined')` подставляет `'not defined'` вместо NULL.

Если бы использовали INNER JOIN — user_id=4 просто исчез бы из результата, и мы бы потеряли данные.
